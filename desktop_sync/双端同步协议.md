# 双端同步协议（Android ↔ 桌面端）

> v23 · 局域网（Wi-Fi）与 USB（adb reverse）共用同一 HTTP 协议。
> PC 端实现：`student_sports_tool/data_center/sync_server.py`（主程序内嵌 + 控制台脚本共用）。
> Android 端实现：`app/framework/LanSyncManager.kt`。

## 0. 自动发现与自动推送（v23.5 设备信任）

- **自动启动**：PC 主程序打开即自动开启同步服务（config `sync_auto_start` 默认开），
  无需手动到数据中心点启动；心跳广播 + USB 轮询同时启动。
- **自动发现（Wi-Fi）**：PC 端 `sync_beacon` 每 3 秒向 `255.255.255.255:9112` 广播
  `{"type":"desktop_online","host":<LAN IP>,"port":<同步端口>,"token":<PC token>,
    "name":<PC 名称>,"timestamp":<ms>}`；
  手机端 UdpDesktopDiscoveryService 收到后存储，设置页「自动发现 PC」一键填充
  地址/端口/token（手机端 token 为空时自动写入）。
- **设备指纹回执（识别是否为自己的设备）**：手机收到心跳后向 PC 回执
  `POST /device/hello`：`{"type":"phone_hello","device_id":"<ANDROID_ID>",
  "device_name":"<型号>","timestamp":<ms>}`；
  PC 写入 config `sync_devices`（name/first_seen/last_seen/trusted），
  数据中心「双端同步」面板展示设备列表，教练点击**信任**后标记
  `trusted=true`，hello 响应携带 trusted 供手机端展示。
- **USB 自动连接**：PC 端 `usb_helper` 每 15 秒检测 `adb devices`，
  对每台在线手机自动执行 `adb reverse tcp:<port> tcp:<port>`，
  手机端未配置地址时自动回退 `127.0.0.1` 即达 PC。
- **自动推送**：手机端开启「自动同步」后——
  1. 数据变更触发的静默自动备份成功 → `AutoBackupScheduler.onBackupCompleted` 钩子 → 自动推送该 zip 到 PC 合并；
  2. 手动「一键备份」成功 → 同样自动推送该备份文件。
  推送静默执行，失败仅写 Logcat（LanSync 标签），不影响备份本身。
- **PC 数据变更反向触发（v23.9）**：PC 端本地编辑（学员/课时/收费增删改）后，心跳通道广播
  `{"type":"desktop_data_changed","host":...,"timestamp":<ms>,"version":<数据版本>}`（5s 节流）；
  手机端 UdpDesktopDiscoveryService 收到后防抖 15s 自动触发一次双向同步。
  合并/恢复路径不广播（防回环）；广播仅作触发信号，拉取/推送仍需 token 鉴权。
  注意：广播不跨网段——PC 与手机须在同一网段才能自动发现与触发。

安全边界：心跳广播为明文 UDP（含 token），token 仅防局域网误投递，非加密保护；
/device/hello 仅登记设备指纹，不传输学员数据；数据通道鉴权与 /upload 一致
（两端 token 一致才放行，都为空时跳过校验）。

## 1. 连接方式

| 方式 | PC 端 | 手机端 syncHost |
|---|---|---|
| 局域网 | 启动同步服务（数据中心 → 双端同步，或 `backup_receiver.py --archive-dir <档案目录>`） | PC 局域网 IP（如 192.168.1.100） |
| USB | 同上 + 运行 `usb_sync.bat`（执行 `adb reverse tcp:8765 tcp:8765`） | `127.0.0.1` |

端口默认 `8765`；token 可选（两端一致，留空跳过鉴权）。
安全限制：Android 端仅允许局域网/回环地址（明文 HTTP 不出内网）。

## 2. 端点

### POST /upload（手机 → PC：整库备份自动合并）

```
Header:
  X-Sync-Token:  {token}          # 启用鉴权时必须
  X-Backup-Name: {fileName}       # 如 smty_backup_20260904_150000.smty_backup
  Content-Type:  application/octet-stream
Body: 备份 ZIP 字节流（BackupRepository.backupToCache 产物）
Response 200: {"code":0, "restored":N, "message":"已合并 N 个档案（...）"}
Response 422: {"code":1, "message":"安全校验拒绝：..."}   # 文件已保存到 save_dir 供人工检查
```

PC 端合并语义（复用 `backup_coordinator.do_restore`）：
- 合并前自动生成「恢复前自动备份」+ 数据库时光机快照，可回滚；
- 新学员自动建档（含性别/学校/电话/父母身高/睡眠/营养/周运动字段）；
- 同名学员：跳过档案覆盖、合并课时明细与课时包（与手动恢复的默认策略一致）；
- 签到照片迁移到 `photos/`；合并后重建 meta_index。
- 合并前经过 `backup_validator.validate_backup_zip`（拒绝路径穿越/可执行文件）。

### GET /sync/students.xlsx（PC → 手机：学员汇总包）

```
Header: X-Sync-Token（启用鉴权时必须）
Response 200: xlsx 字节流（列：姓名 性别 年龄 年级 学校 电话 身高(cm) 体重(kg) 数据更新时间 备注）
Response 404: 无学员可导出
```

### GET /sync/packages.json（PC → 手机：课时包汇总，v23.7 新增，v23.8 起被 pc_data 取代但仍保留）

```
Header: X-Sync-Token（启用鉴权时必须）
Response 200: {"code":0, "packages":[{"studentName","totalLessons","usedLessons"}]}
Response 400/500: archive 未配置 / 导出失败
```

手机端合并语义（v23.7 旧版手机）：学员手机端无课时包 → 新建「PC 同步」包；
已有课时包 → 更新最近一条的总课时与已用（PC 值为准）。
（v23.8 起手机端改用 /sync/pc_data.json 的对账语义。）

列集与 Android `ExcelSync.buildColumnMapping` 智能表头严格对齐；
禁止新增含「高/重/年」等字样的列（会被误映射）。
手机端拉取后经 `ExcelSync.importStudentsFromTabularExcel` 解析，
按 **UPDATE_PART**（同名仅更新身体形态指标）策略合并入 Room。

### GET /sync/pc_data.json（PC → 手机：数据总包，v23.8 新增）

```
Header: X-Sync-Token（启用鉴权时必须）
Response 200: {
  "code":0, "generatedAt":<ms>,
  "packages":[{"studentName","totalLessons","usedLessons"}],   # usedLessons = PC 已上课时（明细推导）
  "lessons":[{"studentName","date","count","content","note"}], # 课时明细全量
  "fees":[{"studentName","date","amount","hours","method","note"}]  # 收费记录全量
}
Response 400/500: archive 未配置 / 导出失败
```

数据源：课时记录.xlsx（明细+汇总）与 收费记录.xlsx，一次性下发。
手机端三步对账（实现：`domain/sync/SyncReconcilers.kt` + `data/repo/PcSyncRepository.kt`，
全部走合并/单调语义，绝不删除手机端任何数据）：

1. **课时包总量对账**（PackageReconciler）
   - PC 空数据（total≤0 且 attended≤0）→ 绝不动手机现值；
   - 手机无包且 PC total>0 → 新建「PC 同步」包；
   - 手机恰一包（不含已退费）→ 设为 PC total（可增可减，修正与加购都落唯一包）；
   - 手机多包 → 与「未退费包总量之和」对账：正差值新建「PC 同步」包，零差值不动；
   - **安全锁**：PC total < 手机包已用 → 拒绝；多包负差值（缩减）→ 拒绝并写同步日志。
2. **PC 消课差值对账**（ConsumptionReconciler）
   - PC 已上课时超出「手机课时行数（热+冷）」的部分 = PC 独录消课，
     按差值折算进手机最近活跃包的 usedLessons（按剩余截断，进度存 pc_sync_state）；
   - 进度单调不减：重复同步幂等；PC 删除消课不回退手机已折算值。
3. **收费记录镜像**（只读，v35 Room fee_records 表）
   - 自然键摘要为幂等主键 REPLACE 入库；PC 为唯一权威源，
     手机端不可编辑，PC 删除的记录手机端保留（删除不传播）。

## 3. 同步时序（手机端「立即同步」）

```
1. pushBackup   : backupToCache → POST /upload → PC 校验+合并 → JSON 结果
2. pullStudents : GET /sync/students.xlsx → ExcelSync 解析 → UPDATE_PART 合并 → 统计反馈
```

## 4. 冲突策略（v23.3 起双向 LWW）

| 场景 | 策略 |
|---|---|
| 手机推 PC：学员不存在 | 新建档案 + 建花名册行（年级编码转 PC 标签） |
| 手机推 PC：学员已存在，手机端更新时间较新 | **刷新 PC 花名册**身体与联系字段（身高/体重/BMI/年龄/性别/学校/电话/遗传字段） |
| 手机推 PC：学员已存在，手机端更新时间较旧/缺失 | 仅合并课时（保留 PC 档案） |
| 手机拉 PC：学员不存在 | 新增 |
| 手机拉 PC：同名学员，PC 端更新时间更新 | UPDATE_PART 更新身体与联系字段 |
| 手机拉 PC：同名学员，PC 端更新时间更旧 | **跳过**（保留手机端较新数据，LWW） |
| 同步包/备份无「更新时间」字段（旧版本） | 按旧行为处理（兼容） |

LWW 依据：PC 端每次保存学员档案刷新 `_meta.students[name].updated_at`（毫秒），
随同步包「数据更新时间」列下发；手机端 `Student.updatedAt`（Room）随备份
`export_meta.json` 上送。年级（两端表示不同）与备注在双向合并中均保留各端现值。
注意：手机→PC 合并**不覆盖年级/备注**；删除操作不传播（防误删放大）。

### 自动对齐时序（v23.1）

```
手机端开启「自动同步」后：
1. 数据变更 → AutoBackupScheduler 防抖 10 分钟 → 静默备份
   → onBackupCompleted 钩子 → pushBackupFile 推送 PC 合并
2. PeriodicSyncWorker 每 30 分钟（有网络时）→ syncNow（推送 + 拉取，LWW 合并）
3. 手动「一键备份」成功 → pushBackupUri 推送
```

## 6. 局域网（同一 Wi-Fi）连不上排查

USB 能通、Wi-Fi 不通的九成原因是 **Windows 防火墙拦截入站**（首次监听时
弹窗被点了"取消"或直接默认拦截；adb reverse 不经过防火墙所以 USB 不受影响）。

按顺序排查：

1. **防火墙**（最常见）：双击 `desktop_sync/firewall_allow.bat`（会弹 UAC，
   点"是"），自动放行 TCP 同步端口 + UDP 9112。
   数据中心启动同步服务时也会自动尝试放行并在日志区提示结果。
2. **手机端地址**：设置 → 桌面同步 → 自动发现 PC（或手动填 PC 的局域网 IP，
   在 PC 端 `ipconfig` 查看"无线局域网适配器 WLAN"的 IPv4 地址）。
3. **PC 端服务在监听吗**：数据中心日志区应显示"服务已启动"；
   浏览器打开 `http://<PC IP>:8765/health` 应返回 OK。
4. **路由器 AP 隔离**：若以上都正常仍不通，路由器可能开启了"客户端隔离/
   访客网络隔离"——登录路由器管理页关闭，或改用 USB（usb_sync.bat）。
5. **PC 换了网络/IP 变了**：DHCP 分配的 IP 会变，重新"自动发现 PC"或手动填新 IP；
   想固定可在路由器给 PC 绑定静态 IP。

## 5. 已知边界

- 排课、体测成绩明细暂不双向同步（手机拉取包不含；手机备份中的 schedules[] PC 端不解析）。
- 桌面端删除操作不会传播到手机（避免误删放大）。
- 每学员独立测评 xlsx（体测明细）仅存 PC，手机整库备份不含、拉取包不含。
- **教练数据两端独立**（v23.6 勘误）：手机端 Coach/CoachSchedule/CoachPayout 等教练体系与 PC 端
  教练档案.xlsx 互不相通；手机备份中的 coaches[] PC 端不解析。
- **课时明细单向可见**（v23.6 勘误，v23.8 部分收窄）：PC 录入的课时明细不下载到手机，
  但 PC 独录的消课数会经 pc_data 对账折算进手机课时包已用（两端剩余课时一致）。
- 手机端课时明细中的 scores（体测成绩 JSON）在合并入 PC 课时表时丢弃（PC 课时表无该列）。
- **退款/缩减不自动传播**（v23.8 安全锁语义，与"删除不传播"同源）：
  手机端退费包不计入对账总量，但 PC 端总课时的缩减不会反向缩减手机包；
  两端退款均需教练在另一端手工同步调整。

## 6. 数据真统一与安全锁（v23.8）

两端模型差异：PC 是「单汇总」模型（每学员一个总课时 + 明细推导已上课时），
手机是「多包」模型（一学员多张课时包，各含 usedLessons）。v23.8 起两端收敛到同一业务事实：

| 数据 | 手机 → PC | PC → 手机 |
|---|---|---|
| 已购课时 | Σ(未退费包 total) 单调写入 PC 汇总（只增不减） | PackageReconciler 对账（见 pc_data 语义） |
| 已消课时 | 课时明细幂等合并，PC 从明细推导 | PC 独录消课差值折算进手机包 usedLessons |
| 收费记录 | 不上送（PC 为唯一权威源） | 只读镜像（fee_records，幂等 upsert） |
| 删除/退款 | 不传播 | 不传播（人工两端处理） |

**安全锁清单**（两端合写路径全部受保护）：

1. PC /upload 与 auto_sync：`backup_validator.reject_wiped_backup` —— 零内容备份
   （0 学员/0 课时/0 课时包）合并进非空档案目录时 422/拒绝，防手机清库后的空备份误导；
2. PC 总课时单调不减：手机推送的 Σ 未退费包小于 PC 现值时不覆盖（防旧备份改小）；
3. 手机包总量经同步单调不减：PC 较旧值/负差值拒绝，任何包 total 不得低于其 usedLessons；
4. PC 空数据（0/0）绝不动手机现值（v23.7.1 原则延续）；
5. 手机消课折算进度（pc_sync_state）单调不减，重复同步幂等。
